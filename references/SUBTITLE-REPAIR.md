# 自动修复规则

## 默认运行顺序

1. 对整门课程执行完整初审，读取课程结构、sequential 发布状态和全部目标 Gallery。
2. 收集初审确认的 NLMCA-010 行首 `>` 问题、NLMCA-012 加粗识别失败，以及 NLMCA-013 发布状态为 `issue` 且 locator 有效的 sequential 小节。其他检查仍只报告。
3. 对每个候选 Gallery 重新读取完整 `play_config`。配置或任何字幕页不完整时，跳过该 Gallery 写入，并继续检查独立目标。
4. 更新完整 `play_config`，只处理获准的字幕问题：能唯一定位时规范加粗空白；范围含糊或空白规范无效时移除该页的 `**` 分隔符。
5. 全部字幕更新尝试结束后，每个至少有一次成功更新的 vertical 发布一次；随后发布每个初审确认有未发布改动的 sequential 小节一次。Sequential 发布会公开该小节当前保存的全部改动，包括本轮字幕修复以外的改动。
6. 只要本轮有字幕修复候选或 sequential 发布候选，就对整门课程执行一次完整复审。最终报告以这次复审读取到的 Studio 状态为准；不开始第二轮修复。

没有可修复或发布候选时，初审就是本轮最终审核。`--audit-only` 也只执行初审，不读取用于修复的额外配置，不更新字幕或发布内容。发布候选必须来自 NLMCA-013 的 `issue` 结果并具有有效 sequential locator；`unverified` 不会触发发布。

## 行首标记处理

- 审核仍按现有检查规则工作：对字幕做一次 HTML entity 解码后，匹配 `^ {0,3}(?:>+ *)+`。这保留现有的行首边界和检测范围。
- 自动修复只删除保存文本中的原始 `>`、`&gt;` 或无分号 `&gt` 前缀及其分隔空格。字幕其他部分保持原始编码和文字。
- 更新整页字幕时保留页码、时间、音频绑定和该页的其他字段；配置中 `show_subtitles` 和其余字段原样保留。
- 只有完整 `play_config`、`time_config` 列表及其中所有字幕都可读取时才写入。更新响应无法确认成功时，不发布该 vertical。
- 写入前还要确认 `show_subtitles` 是布尔值，且每个 `time_config` 条目有正整数 `page`、非负整数 `start`、不早于 `start` 的整数 `end` 和非空字幕；缺少或无效时跳过整个 Gallery。
- 某个 vertical 中多个 Gallery 更新成功后，只发布一次。没有任何 Gallery 成功更新的 vertical 不发布。
- 初审读取不到完整字幕时，NLMCA-010 是 `unverified`，不会成为修复候选。局部修复证据不完整时记录为跳过，其他可确认的 Gallery 继续处理。

## CommonMark 加粗处理

- 以审核使用的 CommonMark 解析结果识别 NLMCA-012 候选，不根据中文、标点或语义猜测加粗范围。
- 只规范同一字幕页中唯一的一对 `**` 分隔符，并且只移动分隔符内侧的空格或制表符。不得增删正文词语、分隔符或其他标点。
- 如果原因是 `ambiguous_bold_span` 或 `spacing_not_repairable`，移除该页所有未转义、非行内代码中的 `**` 分隔符，再用现有解析器复查。保留正文、空白、标点和单个 `*`；由于无法可靠区分分隔符范围，这也会移除该页原本可识别的 `**` 加粗格式。
- fallback 复查确认不再有未识别的 `**` 候选后，才允许将该页写入完整配置，并以 `bold_delimiters_removed` 记录修复原因。其他原因（如 `unpaired_delimiter` 或 `normalization_unverified`）仍安全跳过。
- 同一 Gallery 的其他页可继续处理；加粗问题跳过不阻止同页可安全移除的行首标记。
- 报告只记录页码、未识别标记数量、修复状态和安全跳过原因，不记录字幕原文。

## 报告

最终 JSON 保留原有状态与检查结果，并增加 `repair_summary`：运行模式、修复轮数、每个 vertical 的安全 locator、Gallery 与字幕修复状态、页码和数量、发布状态；若发布 sequential，还记录 `sequential_publications` 中的安全 locator、发布状态和可用 HTTP 状态码。报告不包含字幕文本、API payload、原始异常、媒体名称或认证信息。

修复更新或发布失败时仍执行最终完整审核；失败结果与最终检查结果分别保留，最终审核不会触发新的修复。
